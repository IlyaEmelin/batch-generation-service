### 2.1. Отдельно найденный баг

При первом же smoke-прогоне `max_planned_input_tokens` оказался равен **2**.
Причина: transformers 5.x возвращает из `apply_chat_template` не список, а
`BatchEncoding` с ключами `input_ids`/`attention_mask`, поэтому `len()` давал 2.
Следствие — бюджет 1500 токенов фактически не проверялся, а обрезка отзывов не
срабатывала. `count_chat_tokens` исправлен: поддерживаются список (4.x),
`BatchEncoding` (5.x) и вложенный батч. После правки `max_planned_input_tokens`
совпал с фактическим `max_input_tokens` (1399).

## 3. Эксперименты и итоговый прогон

1. Smoke: 3 товара с `json_object` и без. Сервер принимает параметр; без флага
   модель оборачивает JSON в ``` (1 из 3), с флагом — 0 из 3. Решение: включить
   флаг в финальной конфигурации.
2. Валидатор: проверены русская карточка, ```-обёртка, CJK в description/tags/
   pros, пустой `cons`. Все кейсы дают ожидаемый результат.
3. Сетка параметров (`dev.jsonl`, 40 товаров, `max_attempts=1`): базовая точка
   0.550; 0.575 у temperature 0.3/0.7, top_k 20 и rep 1.1 — это ±1 карточка,
   шум. `rep_penalty_1.2` падает до 0.300, `max_tokens_250` даёт 7 обрывов JSON.
   Итог: параметры не менялись.
4. Sweep `concurrency` 1/4/16/32 по 24 товара: 0.167 / 0.543 / 1.017 / 0.991
   карточки/с, насыщение на 16.
5. Полный прогон 300 товаров: 281 валидная (0.9367), `retry_rate` 0.3533,
   346.38 с, 20.847 ₽/1000.
6. API-сравнение (OpenRouter, `gpt-oss-20b`, 30 товаров): 29/30 (0.9667),
   47.825 ₽/1000; на тех же 30 товарах локально 24/30 (0.800).

## 6. Остаточные риски

- 8 карточек из 300 не исправили CJK за три попытки; нужен постфильтр или
  constrained decoding.
- Локальная подвыборка тех же 30 товаров даёт 0.800 против 0.937 на всех 300 —
  сэмпл смещён по трудности, выводы об API нужно формулировать осторожно.
- T4 не измерялась: 346.38 с — локальная GPU в троттлинге, перенос на T4 не
  подтверждён.
- `cons` и число предложений остаются основными причинами повторов; следующая
  правка промпта должна проверяться на ≥150 товарах.
