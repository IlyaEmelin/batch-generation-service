# Отчёт по проекту

> Все числа в этом файле берутся из `outputs/report.json`, который считается из сохранённых результатов прогона. Пока прогоны не выполнены, разделы содержат только структуру — вписывать значения вручную нельзя.

## Финальный конфиг
- модель, dtype, параметры vLLM
- стратегия длинного входа
- сколько повторов при браке формата и почему

## Параметры генерации
- таблица экспериментов и выбранные значения
- что изменилось при подборе: доля валидных, длина описания, выходные токены

## Сравнение с моделью через API
- таблица: качество, токены, скорость, стоимость
- какие ошибки API встретились и как обработаны
- вывод: что дешевле, что качественнее на этой задаче

## Замеры
- доля валидных карточек: ... , разбивка брака по причинам
- скорость: таблица throughput/latency по concurrency, выбранная точка
- время на весь бенчмарк: ...
- стоимость: на своём сервере ... ₽/1000 из полного прогона, через API ... ₽/1000 из прогона этапа 6

## Длинный вход
- какую стратегию выбрал и почему

## Оптимизации
- выбор точности: float16 или INT4, с обоснованием (замер по желанию)

## Как воспроизвести
- команда запуска vLLM: модель, `--dtype half`, `--max-model-len 4096`, `--gpu-memory-utilization 0.9`, `--enforce-eager`, порт 8000
- окружение: GPU, драйвер, версия CUDA, версии torch и vLLM
- команды: `python run_batch.py ...`, `python check_metrics.py`, `python compare_api.py`
- модель API и дата прогона (из `outputs/report.json`)

## Артефакты
- `outputs/predictions.jsonl` — строка на каждый `product_id`, поля `input_tokens`, `attempts`, `validation_errors`, `valid`
- `outputs/report.json` — конфиг прогона, метрики, таблица concurrency, расчёт стоимости, сравнение с API
- `outputs/api_predictions.jsonl` — сырые ответы API-прогона, если он выполнялся
- `scripts/profile_data.py` — профиль наборов в токенах (числа раздела «Длинный вход»)

## Стоимость и решение
- расчёт обоими способами
- при каком объёме выгоднее API
- итог: свой сервер или API и почему
